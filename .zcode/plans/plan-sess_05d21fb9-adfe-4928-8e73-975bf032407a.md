# Конструктор характеристик товара и страница товара

## Подход
Характеристики описываются декларативно (шаблоны по категориям), форма добавления и просмотр товара рендерятся из одних и тех же шаблонов — поэтому у покупателя гарантированно отображается «тот же конструктор», но только для чтения.

## 1. Шаблоны характеристик — новый `src/app/core/specs.ts`
- Категории: `phone` (Телефоны), `laptop` (Ноутбуки)
- Для каждой категории — по **18 характеристик** (больше минимальных 15), каждое поле: ключ, подпись, тип (текст / число / выпадающий список с вариантами):
  - **Телефоны:** бренд, модель, год выпуска, ОС, диагональ экрана, разрешение, тип матрицы, процессор, ОЗУ, встроенная память, основная камера, фронтальная камера, аккумулятор, быстрая зарядка, SIM, защита от воды, цвет, вес
  - **Ноутбуки:** бренд, модель, год, ОС, диагональ, разрешение, матрица, процессор, ОЗУ, тип памяти, накопитель, тип накопителя, видеокарта, батарея, порты, подсветка клавиатуры, вес, цвет

## 2. Модель — `src/app/core/models.ts`
В `Product` добавляются: `category: 'phone' | 'laptop'` и `specs: Record<string, string>`.

## 3. Форма добавления — `src/app/pages/add-product/`
- Вверху select «Категория» (Телефоны / Ноутбуки); пока не выбрана — характеристики скрыты
- После выбора категории рендерится конструктор: поля нужного типа (select с вариантами для памяти/камер/разрешений и т.д., текст для бренда/процессора, число для веса)
- Кнопка «Опубликовать» активна только когда заполнены все характеристики
- `ProductsService.addProduct` сохраняет категорию и характеристики

## 4. Страница товара — новый `src/app/pages/product/` + роут `/product/:id`
- Фото, название, описание, категория
- Таблица характеристик из того же шаблона (`SPEC_TEMPLATES[category]` × сохранённые значения) — только чтение, без инпутов
- Состояния «Загрузка…» и «Товар не найден»

## 5. Главная — `src/app/pages/home/`
Карточки становятся ссылками на страницу товара (`/product/:id`).

## 6. Правила Firestore — `firestore.rules`
Добавить в валидацию создания товара `category in ['phone','laptop']` и `specs is map`. После правок нужно заново вставить правила в консоль Firebase (Rules → Publish).

## Проверка
`ng build`, затем в браузере: добавить телефон и ноутбук под тестовым продавцом, открыть карточки как покупатель, проверить отображение характеристик. В конце — коммиты и пуш.
